# Monitor Process

## Purpose

**Monitor Process** gives administrators visibility into running process instances — their status, active tasks, and overall throughput. The monitoring experience depends on the process engine configured for your subscription: **Camunda 8** shows a live embedded dashboard, while **Camunda 7** links to the Camunda Cockpit with SSO credentials generated by the platform.

---

## Key Concepts

| Term | Description |
|---|---|
| **Process Instance** | A single running execution of a deployed process, identified by a unique instance ID. |
| **Process Definition Key** | The key of the deployed process the instance was started from. |
| **Business Key** | Your application's record ID linked to the instance (set at start time). |
| **Camunda Cockpit** | The built-in Camunda 7 monitoring UI — shows active instances, incidents, and variable inspection. |
| **SSO Login** | Single-sign-on credentials generated by Appflexor to access Camunda Cockpit without a separate account. |

---

## Step-by-Step

### 1 — Open Monitor Processes

1. Navigate to **Orchestrate → Configure Processes**.
2. Click the **Monitor Processes** tab.
3. The view rendered depends on your subscription's process engine.

---

### Camunda 8 — Embedded Process Monitor

The monitor shows a live list of process instances directly inside Appflexor.

**Filter and search**

- Use the **search bar** at the top to filter instances by process name or ID.
- Clear the filter with the **✕** button to return to the full list.

**Reading the list**

Each row shows:

| Column | Description |
|---|---|
| **Title / Name** | Human-readable process name from the deployed definition |
| **ID / Key** | Process definition key or instance ID |
| **Status** | Active, completed, or incident |

**Investigating an instance**

- Click a row to expand or navigate to the instance detail.
- Inspect active tasks, current variables, and the path taken through the BPMN diagram.

---

### Camunda 7 — Cockpit Access

For Camunda 7 subscriptions, monitoring is done through the **Camunda Cockpit** — a separate UI embedded within your platform.

#### Step 1 — Get your SSO Login

1. Click **Get Camunda Login** on the Monitor Processes tab.
2. The platform calls the `sso.camunda` service and generates temporary credentials tied to your user account.
3. Your **Username** and **Password** appear in the panel.

#### Step 2 — Copy credentials

- Click **Copy** next to the username field to copy it to your clipboard.
- Click **Show** to reveal the password, then **Copy** to copy it.
- If your password has expired or needs to be reset, click **Reset** — the platform calls the `reset.password` service and issues a new password.

#### Step 3 — Open Cockpit

1. Click **Open Cockpit** — this opens Camunda Cockpit in a new tab at `/camunda/app/cockpit/default/#/login`.
2. Paste your username and password into the Cockpit login form.
3. You are now logged in and can:
   - View all running process instances.
   - Inspect active tasks, incidents, and variables per instance.
   - Drill into the BPMN diagram with the current token position highlighted.
   - Resolve incidents manually if a process step has failed.

---

## What to Look For

| Indicator | Meaning | Action |
|---|---|---|
| **Active instances** | Processes currently running and awaiting user action | Normal — tasks are in progress |
| **Incidents** | A step has failed (e.g. a connector error or unhandled exception) | Inspect the incident detail, fix the root cause, and retry or cancel the instance |
| **Suspended instances** | Instances deliberately paused by an administrator | Resume or cancel as appropriate |
| **Completed instances** | Processes that have reached an end event | Archived — no action needed |

---

## Best Practices

- **Check for incidents daily.** Unresolved incidents block process flow and accumulate over time — build a habit of reviewing the monitor each morning.
- **Use Business Keys to correlate.** When investigating an instance, cross-reference the Business Key with your application's record ID to quickly find the associated form data.
- **Reset Cockpit passwords periodically.** SSO credentials are scoped per user. If a colleague needs access, they should get their own login from the Monitor tab rather than sharing credentials.
- **Don't cancel instances without investigation.** Cancelling a running instance is irreversible. Always inspect the current state and incident details before cancelling, and notify the process owner.
